# Demo 前端功能与 Presentation 展示指南

更新日期：2026-11-23。当前界面为英文，使用真实本地 M4 检索和学校网关 M5 生成；不是模拟回答。启动与知识库准备见 [本地配置与启动](Demo_本地配置与启动_中文.md)。

前端正式位置为 `demo/frontend/`，后端为 `scripts/demo/`。两份中文指南随仓库存放，不依赖仓库外的 `中文/` 目录。批量演示可直接使用 [examples/demo/batch_demo_questions.jsonl](../../examples/demo/batch_demo_questions.jsonl)。

## 1. 可以展示哪些功能

### Knowledge base：知识库

- 浏览本机目录，选择已经准备好的 M4 工作目录。
- 校验文档／切分文件哈希、索引身份、嵌入模型版本及维度。
- 展示知识库名称、目录、文档数、嵌入模型、校验状态和加载时间。
- 查看 C / Hybrid / k=5、candidate_k=30、RRF=60、1024-token 证据预算和打包策略。
- 更换或卸载知识库。任务运行期间不能切换。

这是加载现有知识库，不支持任意 PDF／Word 自动建库。新闻证据和模型缓存保留在本机；实际问答会把问题和所选证据发送到网关。

### Chat：单题问答

- 在聊天框输入问题，Enter 发送，Shift+Enter 换行。
- 每题独立处理；历史消息只用于显示，不作为多轮上下文发送。
- 展示实际检索、生成、审核、修复阶段；未发生的阶段不伪造。
- 点击 `[S1]` 等引用，展开文章标题、日期、原文 URL 和证据片段。
- 复制回答、查看缺失信息、运行详情和错误原因。
- 请求停止；正在执行的操作可能需要等待返回，已经产生的调用和费用不会被撤销。
- 清空页面消息不会删除后端保存的运行文件。

### 协议选择

- **G0 · Basic answer**：要求模型在正文中给引用，不执行引用硬校验。
- **G1 · Citation validation**：结构化生成，检查引用与逐字原文定位。
- **G2 · Review and repair**：在 G1 基础上自动审核，必要时最多修复一次，修复后再次审核。

正常情况下，G0／G1 每题 1 次调用；G2 每题 2 次，触发修复时可到 4 次。G2 不保证更正确。G0 的非结构化引用不一定能像 G1／G2 一样定位原文。

### Batch questions：批量问答

- 选择本地 JSONL，或用 **Paste JSONL instead** 粘贴内容。
- 后端验证格式、题号、空问题、重复 ID 和额外字段；不接受答案与评分标签混入生成输入。
- 运行前预览题目并确认协议，点击 **Start batch** 才会开始真实调用。
- 显示进度、逐题任务状态、独立答案状态、耗时和结果详情。
- 支持停止后续处理，保留完成、失败、取消和未执行的题目。
- 每次只接受一个活动任务，不同时运行聊天和批量任务。
- 运行后导出 **Answers JSONL**、**Results CSV** 和 **Run summary JSON**。

JSONL 只包含 `id` 和 `question`，最多 100 题、文件上限 1 MB。完整运行17题时，G1通常为17次调用，G2通常为34次，修复会增加调用。不要为了展示反复运行正式保留集。

## 2. 页面上的状态怎样解释

答案状态和任务状态是两套概念，不能混为“对／错”。

### 答案状态

- **Answered / ANSWERED**：系统已生成并接受回答；不代表人工确认正确。
- **Partial answer / PARTIAL**：回答部分内容，同时说明其余所问信息缺失。聊天／详情中有蓝色独立提示，批量表有独立答案状态。
- **Insufficient source information / INSUFFICIENT_SOURCES**：材料不足，明确拒答；聊天中为黄色提示。
- **Basic answer · not validated / PROMPT_ANSWER**：G0 的基础回答，没有经过引用硬校验。
- **Answer failed / ERROR**：请求、解析、契约或审核流程失败，没有可接受的最终答案；显示错误原因。

这些状态来自系统，不是人工评分。人读出“部分正确”但模型漏检时，系统仍可能返回 ANSWERED。例如开发集 `m5_dev_002` 的人工 PARTIAL 不能自动当成模型 PARTIAL。

### 任务状态

批量表的 **Task status** 可显示 Processing、Completed、Failed、Cancelled、Not executed。**Answer status** 单独显示上述答案状态。运行前等待处理的行当前也显示 Not executed；整体进度可看出任务是否仍在进行。

一次材料不足的拒答，可以同时是 **Task status: Completed**。Completed 只代表该题处理完成，不是答案正确。

### Run details：运行详情

可以查看协议、模型、原始运行状态、输出检查、自动审核结果、端到端耗时、调用次数、输入／输出 token、修复次数和费用。

- Unknown 是未知，不能当作 0。
- 单个 API 调用耗时中位数／P95，不是每题的端到端耗时。
- 修复次数为 0，仅表示未触发修复，不能证明不存在错误。
- 引用能定位原文，不等于事实和问题覆盖都正确。

## 3. 可直接使用的演示问题

### 正常回答与引用（已在当前 Demo 验证）

```text
Which celestial body prompted the 2006 vote on Pluto?
```

已观察到回答 Eris 并带 `[S1]`。点击引用，展示对应新闻原文；模型再次运行的具体措辞和返回情况可能变化。

### 材料不足／正确拒答（已在当前 Demo 验证）

```text
What are the passport numbers of the Australians missing in Nepal?
```

已观察到明确说明报道没有提供护照号码。新闻中出现失踪人数，不表示包含护照号码。黄色材料不足提示是预期表现，不是接口失败。

### 部分回答（候选示例，不能承诺每次都返回 PARTIAL）

```text
Which celestial body prompted the IAU's 2006 vote on Pluto, and what was the passport number of the astronomer who discovered it?
```

预期：回答 Eris，并明确材料未提供发现者的护照号码。只有系统实际返回 PARTIAL 才会显示蓝色 Partial answer；不要手工修改展示结果或把预期当成已验证记录。

## 4. 建议的 3 分钟展示流程

### 第一步：展示本地知识库（约 30 秒）

提前准备数据并启动服务。在 Knowledge base 页说明文档数量、索引与本地嵌入模型，然后进入 Chat。

可说：

> 系统先从本地知识库检索证据，再将问题和所选证据交给生成模型。

### 第二步：正常回答与引用（约 60 秒）

选择 G1，询问 Eris 题。点击 `[S1]`，展示原文与来源链接。

可说：

> 用户可以追溯答案依据，而不只是看到模型的一段结论。引用可定位，但正确性仍需另外核验。

### 第三步：展示拒答（约 30 秒）

询问护照号码，展示黄色材料不足提示。

可说：

> 资料没有所问字段时，系统应明确说明缺失，而不是编造答案。这是正常完成的拒答，不是运行失败。

### 第四步：两题 G2 批量与导出（约 60 秒）

把前两题导入为 JSONL。选择 G2，展示逐题进度、完成与拒答、调用次数和导出按钮。当前已有一次两题 G2 真实记录：正常回答与拒答各一题，共4次调用；它只是功能验证，不是新的独立评估结论。

可说：

> 批量模式记录每题的执行和引用。G2 增加审核，但也增加调用开销；自动审核通过不等于答案已被人工证明正确。

## 5. 展示前检查

1. 前后端已启动，页面显示 Backend connected；注意这不证明学校网关鉴权一定成功。
2. 知识库显示 Knowledge base ready。
3. 使用合成演示题或已公开的开发题，确认网络、网关额度及权限。
4. 准备两题 JSONL 和一份历史真实结果作为网络故障备用，展示时明确区分历史记录与现场运行。
5. 不在前端、投屏、终端输出或导出文件中显示密钥。
6. 不承诺现场触发修复或 PARTIAL；模型行为不完全确定，按实际结果解释。
7. 不把 Demo 的输出状态当作人工评分，也不把演示运行混入冻结的正式分数。

## 6. 当前边界

- 无公网部署、登录与多用户隔离；仅用于本机展示。
- 不自动下载／构建知识库，不支持任意文档上传后立即问答。
- 不实现自动人工评分、正确率或事实覆盖率计算。
- 刷新页面不恢复聊天或批量界面，也不自动重发请求；后端保留的任务可按 ID 导出。
- 停止是协作式停止，不能撤销已经提交的模型调用。
- 学校网关价格未核验，费用保持未知。
