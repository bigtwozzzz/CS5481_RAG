# M5 新题集标注与复核规范

本题集用于后续 M5/M6 评估。开发集 15 题（12 可答、3 不可答），保留集 25 题
（20 可答、5 不可答）。目前是代理逐篇核对后的候选版本，尚无独立真人复核。
`agent_source_check=PASS` 不代表人工批准，也不代表模型回答正确。

## 文件用途

- `m5_dev.json`、`m5_holdout.json`：金标准，含参考答案、必要事实、原文引用和审核信息。
- `inputs/m5_dev.questions.jsonl`、`inputs/m5_holdout.questions.jsonl`：仅有 `id`、`question`，可供 A/B 入口读取。
- `m5_event_registry.json`：事件分组、相关文章和语料扫描规则。
- `m5_exclusion_audit.json`：历史 QA、示例与已保存检索结果的排除清单、输入文件指纹。
- `human_review.csv`：独立人工审核工作表，不作为模型输入，也不把未填写内容当作通过。
- `m5_dataset_manifest.json`：语料来源、题集指纹、数量、封存状态和限制。

金标准和审核 CSV 只能由评估器与审核者使用。生成输入不得包含答案、必要事实、
证据标签、可答性、不可答原因、事件或 split 字段。按 `id` 关联，不按行号猜测对应关系。

## 标注单位和证据

问题为英文，依据当前新闻语料快照中的报道内容作答，不要求外部知识或联网查询。
报道中的未来计划、研究结论和厂家声明须保留原有归属与限定，不能当成独立验证的事实。
参考答案只是一种表述，不能用字符串完全相等判断正确性。

`required_facts` 尽量拆成可分别打分的最小必要事实，每项权重为 1，并关联 evidence ID。
时间、单位、近似值、对象和条件都属于事实含义。例如“约 46 米”不能错配给另一艘船；
“计划 2030 年”不能改写成“已在 2030 年开通”。同一引文可以支撑多个独立事实。

`gold_evidence` 是可答题的证据，不是预先指定的检索 chunk。
每段引用保留 document ID、URL、标题、发布时间、原文 body 哈希和精确字符范围。
范围基于原始 `body_text` 的 Python Unicode 字符索引，左闭右开；不是字节或 token。
多个引用可以共同支持答案。可接受的同义证据由审核者确认后补充，不能只因未命中
指定引文就断言答案无依据。

## 事件隔离与历史排除

事件以具体研究、发现、政策、产品发布或事故为单位，不以主题或文章 ID 为单位。
同一事件的所有问题和语料候选文章必须归于同一个 split。
事件规则在整个 3,152 篇文档快照上做词法扫描；还需要审核者检查别名与语义上的相关报道。
规则可能保守地收入相邻事件文章，这不会把同一事件拆到不同 split。

原 M4 的 27 条 QA、历史演示以及已保存的检索结果保持原样。
新题的锚定文章及事件候选文章全部避开历史结果引用过的 document ID。
已知历史事件（尼泊尔洪灾、Pluto/Eris 等）也整体排除，不能改写成“新题”。
开发集可用于调参；保留集在本轮建设中只做原文核对和结构校验，未执行向量检索、
生成或配置选择。题集作者看过标注，不能声称作者对保留集盲测。

## 不可答题和难负例

不可答题均与报道主题密切相关，要求一个报道未给出的具体事实。
不得把检索失败、预算不足或 API 故障作为不可答标签的依据。

每题保留 `no_answer_reason`、具体缺失信息、`context_evidence` 和
`unanswerability_audit`。`context_evidence` 证明题目相关或说明信息尚未确定，
不冒充缺失答案的正面证据，因此不可答题的 `gold_evidence` 和 `required_facts` 为空。
语料审计包括全文事件候选扫描、候选文章列表和缺失字段相关上下文；没有调用检索器。
词法扫描没有命中不等于数学上证明全库不存在答案，应结合完整原文核对。

人工复核时逐题执行：

1. 阅读完整锚定报道，而非只读引用片段。
2. 阅读审计中的相关文章与字段上下文，检查事件别名或其他可能提供答案的报道。
3. 确认问题未把“没有披露”误当作“值为零”，未把计划当作承诺，未偷换单位或主体。
4. 检查相近数字是否属于别的对象。例如已有中转航班票价不能回答新直飞航线的精确票价。
5. 找到明确答案时改标可答并补足证据；存在歧义时先标争议，不强行保留不可答标签。

## 独立人工审核流程

由实际审核者填写 `human_review.csv` 的 reviewer、各检查项、decision 和 notes。
decision 可填 `APPROVE`、`REVISE`、`DISPUTED`；未审核继续保留 `PENDING`。
不可答题必须填写 `unanswerability_confirmed`；可答题该项可记 `N/A`。
争议题由另一人复核并填写 adjudicator、adjudication。

当前所有 human reviewer 均为空，状态均为 PENDING；没有将代理审核伪装为真人审核。
收集真实审核结果后再更新 JSON 的 human review 字段。修改金标准、输入或事件映射时
必须产生新版本、记录修改原因并更新 manifest 的 SHA-256，不保留旧哈希假装未改变。
独立保留集正式运行前应完成复核和最终封存。

## 封存和后续使用

保留集金标准和纯问题输入已设为只读，manifest 保存 SHA-256。
这是防止意外修改和检测变更的程序性封存，不是加密或访问控制。
真人审核表保留可写；审核只读取题目和来源，不需要运行保留集检索。
保留集结果一旦被用于修改配置，后续就必须如实报告测试暴露，不能仍称为同一轮独立测试。

本轮不生成模型质量指标，不运行 API，不将模拟案例并入正式评测结果。
后续人工评答案时分别记录完整性、正确性、引用支持和覆盖、拒答合理性。
PARTIAL 单列，ERROR 不算正确拒答，所有比例报告分子与分母。

## 仅结构与原文校验

在仓库根目录运行：

```bash
.venv/bin/python -m scripts.m6_evaluation.validate_qa
```

脚本只检查 JSON、指纹、事件映射、历史排除、原文字符范围和输入隔离。
没有模型加载、检索、API 或自动 judge。它不能替代独立人工语义审核。
